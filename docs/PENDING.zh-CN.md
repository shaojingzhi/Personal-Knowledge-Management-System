# 待办事项

## 当前需要加固的点

- 增加 Telegram Bot 的身份校验和白名单限制，确保只有可信发送者可以触发流程。
- 提高 Telegram 媒体下载与重试的稳定性，避免网络波动或 API 抖动导致整次处理失败。
- 对链接、说明文字、截图、粘贴文本等混合输入增加更清晰的校验逻辑。
- 明确并固定当前主输入约定：对于“文字内容主要在一张分享图里”的帖子，Telegram 接收小红书分享图应作为优先可用输入形态。
- 明确记录当前限制：如果帖子核心内容分散在多张图里，或一张分享图无法承载主要信息，当前方案仍然不够好用，需要后续继续研究。
- 继续避免网页整页内容污染 `raw.json`，减少导航、评论、推荐内容带来的噪声。
- 用更可靠的页面 readiness 检查替代固定等待时间。
- 当标题、正文和图片信息都过少时，给出更明确的失败原因。
- 避免重新索引同一条记录时因中途失败导致原向量被临时删空。
- 加强 `source_ids` 校验，避免答案声称引用了其实并未检索到的来源。
- 在 `raw.json`、`normalized.json`、`answers.json` 中加入模型与版本元数据，方便后续比对和排查。
- 保持运行时配置和 README 一致，确保本地 `.env` 自动加载行为稳定。

## 近期优先实现的内容

- 将 Telegram 消息接入作为新的主入口持续完善。
- 将 Telegram 原始消息与附件稳定落盘保存。
- 在保存 `raw.json` 的同时，补齐 Telegram 图片与附件的下载或缓存能力。
- 为“单张分享图即可承载主要文字内容”的小红书输入补上 OCR，让文字真正进入标准化链路。
- 为“图片为主”的 Telegram bundle 增加对本地下载资产的真实读取，而不只是把 `asset_paths` 丢进 prompt。
- 为图片型、截图型输入补齐 OCR 或多模态提取能力。
- 建立一套生成质量评估方法，至少覆盖：输入覆盖度、问题抽取准确性、答案可用性、以及 grounding 质量。
- 建一个轻量的评测样本集或人工检查清单，用于抽查生成问题和答案的质量。
- 强化标准化失败后的重试、解析和排障能力。
- 在 `answers.json` 之外输出适合阅读和归档的 Markdown 版本。
- 先将生成结果重新拼装成更适合阅读的 Markdown，再做本地归档和 Telegram 回推。
- 增加 Telegram 回推能力，把简要答案和摘要发回给你。
- 将“所有问题和答案”都接入向量存储，而不只是问题 embedding，方便后续统一检索、整理和归档。
- 增加 bot-loop 编排、重试和失败告警。
- 增加从接入、标准化、索引、生成到分发的全链路状态持久化。
- 为不依赖外部 API 的存储层和工作流 glue code 补一批轻量测试。

- 收紧收藏页帖子选择器，减少误抓。
- 更严格校验目标收藏夹，而不是只依赖 `XHS_FAVORITES_URL`。
- 扩展更多 note URL 规则识别。
- 为“列表可见但详情不可见”的帖子提供降级采集路径。
- 为大收藏夹支持分页或增量滚动。
- 增加本地搜索或复习界面。
- 如果当前相似度质量不够，再增加 rerank 或更好的 query 构造。
