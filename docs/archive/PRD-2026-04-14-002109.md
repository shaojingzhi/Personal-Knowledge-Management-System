# XHS Interview Answer Copilot PRD v2

## Overview

Build a personal-use system that turns Xiaohongshu interview posts shared from a phone into structured questions and AI-generated answers. The primary path is message-driven ingestion through Telegram, followed by local artifact storage, LangGraph-based normalization, vector retrieval, and RAG answer generation.

## Product Goal

Help a job-seeking developer quickly turn saved interview content into reusable study material without depending on fragile Xiaohongshu web automation.

## Success Criteria

- A user can send a link, text, or screenshots to the bot from mobile.
- The system stores a replayable raw bundle locally.
- The system produces structured interview questions from text-first inputs.
- The system retrieves similar prior questions before generating answers.
- The system saves detailed and concise answers locally and can send a concise result back to Telegram.

## Core Scope

- Telegram Bot as the primary ingestion channel.
- Unified `SourceBundle` input model for Telegram now and Feishu later.
- Local raw bundle persistence with attachment download.
- Text-first normalization with LangGraph and structured output.
- Local vector indexing and similarity retrieval.
- RAG answer generation for concise and detailed answers.
- Local JSON and Markdown artifact output.
- Telegram reply path for summaries and answers.

Core scope accepts screenshot-heavy bundles, but only text-first processing is guaranteed until optional OCR or multimodal extraction is added.

## Optional Scope

- OCR or multimodal reading for screenshot-heavy bundles.
- Optional web enrichment for reachable Xiaohongshu links.
- Additional source adapters such as Feishu.
- Bot-loop orchestration, retries, and task-state tracking.
- Optional legacy web collector kept only as a best-effort enrichment path.

## Non-Goals

- Fully autonomous Xiaohongshu private messaging in phase one.
- Reverse-engineering Xiaohongshu private APIs.
- A full web UI before the ingestion-to-answer loop works.
- Requiring web-side Xiaohongshu accessibility for core success.

## Users

- Primary user: a job-seeking developer collecting interview content for later review.

## Core Workflow

1. User sends a Xiaohongshu link, copied text, or screenshots to a Telegram Bot.
2. The system stores the incoming message as a replayable `SourceBundle`.
3. The system extracts useful text from message text, captions, and later media.
4. LangGraph normalizes the source content into structured interview questions.
5. The system indexes normalized questions in a local vector store.
6. The system retrieves similar historical questions for grounding.
7. LangGraph generates concise and detailed answers.
8. The system writes local artifacts and optionally sends a Telegram summary back.

## Technical Direction

- Python as the implementation language.
- Telegram Bot API as the primary inbound and outbound channel.
- `SourceBundle` as the shared source abstraction.
- LangGraph for normalization and answer workflows.
- Pydantic for typed schemas.
- SQLite for local persistence and lightweight state.
- Local-first vector storage for retrieval.
- OCR or multimodal models as optional media enhancement.
- Optional web enrichment for reachable Xiaohongshu links.

## Risks

- Network access to Telegram or model providers may require a proxy.
- Text-only normalization will underperform on screenshot-heavy posts until OCR is added.
- Retrieval quality depends on indexing quality and threshold tuning.
- Users may send mixed-content bundles that require better validation and source selection.

## Ralph-Oriented Scope Split

### Core Stories

1. Bootstrap project and config loading.
2. Ingest Telegram links, text, and media.
3. Persist raw Telegram bundles and attachments.
4. Normalize text-first source bundles into structured questions.
5. Index normalized questions into vector storage.
6. Generate retrieval-augmented concise and detailed answers.
7. Persist artifacts locally and produce Markdown output.
8. Send answer summaries back to Telegram using previously generated artifacts.

### Optional Stories

9. Add OCR or multimodal media extraction for screenshot-first bundles.
10. Add optional web-side enrichment for reachable Xiaohongshu links.
11. Add bot-loop orchestration, retries, and task tracking.
12. Add another source adapter such as Feishu using `SourceBundle`.
