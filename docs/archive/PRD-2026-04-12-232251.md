# XHS Interview Answer Copilot PRD

## Overview

Build a personal-use automation system that accepts Xiaohongshu interview posts from a mobile-triggered entry point, extracts useful question content from links, text, and images, generates both detailed and concise answers with an LLM, stores the outputs locally, and pushes a copy back to Telegram for mobile review.

## Goals

- Accept Xiaohongshu post links, screenshots, or copied text from a mobile-triggered ingestion channel.
- Extract text content from post body, captions, and images, then normalize it into structured interview questions.
- Reuse previously answered similar questions through vector retrieval before generating fresh answers.
- Generate detailed and concise answers suitable for review before interviews.
- Persist raw and processed artifacts locally for search, debugging, and future expansion.
- Push concise summaries and links to Telegram.

## Non-Goals

- Fully autonomous Xiaohongshu private messaging in the first phase.
- Reverse-engineering private APIs in the first phase.
- Building a full web UI before the core automation works.
- Making web-side favorites polling the only supported ingestion path.

## Users

- Primary user: a job-seeking developer collecting interview posts for later review.

## Key Workflow

1. User shares a Xiaohongshu post link, screenshots, or copied content from the phone to a Telegram Bot.
2. Ingestion service receives the Telegram message and stores the raw input bundle locally.
3. Service extracts useful source text from message text, attachments, and any reachable web metadata.
4. OCR or multimodal extraction converts screenshots and images into text.
5. LangGraph normalizes noisy content into structured interview questions.
6. Normalized questions are indexed and matched against similar historical questions in a vector store.
7. LangGraph generates a detailed answer set and a concise answer set using retrieved context when available.
8. Service stores JSON and Markdown artifacts locally.
9. Service pushes a Telegram summary and answer package back to the user.

## Technical Direction

- Python as primary implementation language.
- Telegram Bot API as the primary mobile ingestion and delivery channel.
- Playwright as an optional fallback for reachable web-side metadata extraction.
- LangGraph for stateful AI workflow orchestration.
- Pydantic for typed schemas and structured LLM outputs.
- SQLite for MVP persistence.
- A local-first vector store for question similarity retrieval and lightweight RAG.
- OCR or multimodal models for screenshot-heavy interview posts.

## Risks

- Users may share inconsistent combinations of links, screenshots, and text that require robust ingestion validation.
- Some Xiaohongshu links may remain unreachable on the web, so screenshots and copied text must be first-class inputs.
- OCR quality may vary for dense image posts.
- Bad retrieval quality may inject irrelevant prior answers unless indexing and similarity thresholds are tuned.
- Telegram delivery and LLM APIs need retry and error handling.

## MVP Stories

1. Bootstrap Python project skeleton and configuration loading.
2. Implement Telegram Bot ingestion for links, screenshots, and text messages.
3. Persist raw Telegram message bundles and attachments locally.
4. Implement multimodal text extraction and normalized question schema.
5. Implement vector indexing for normalized interview questions.
6. Implement retrieval-augmented answer generation for detailed and concise outputs.
7. Implement local artifact storage and Telegram dispatch.
8. Implement bot-loop orchestration, task status tracking, retries, and alerts.
9. Add optional web-side enrichment for reachable Xiaohongshu links.
